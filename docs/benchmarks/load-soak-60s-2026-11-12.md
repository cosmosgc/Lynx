# Local 60-second movement load sample — 2026-11-12

This run extends the five-second instrumentation smoke to one minute with eight
headless clients. It is an in-process Windows sample, not a deployed capacity
benchmark: the server and clients share one process, and the run does not inject
database latency or include TLS and network-interface costs.

## Command

```powershell
cargo run --release -p lynx_load_harness -- --clients 8 --duration-seconds 60 --operations-per-second 100 --scenario movement --sample-interval-seconds 5 --samples-csv target/soak-smoke/movement-60s-samples.csv
```

The load target was met with no queue rejections, authority tick failures,
overruns, or server queue-full events. Mean tick work was 0.4101 ms and reply
p95 was 31.04 ms overall; first and last five-second reply p95 values were
30.97 ms and 31.07 ms. Delta socket writes completed for 5,990 frames totaling
2,722,694 bytes, with no write failures. Combined harness RSS grew by 11.8 MiB
and had not visibly plateaued by the final sample. This does not isolate server
memory or prove a leak. The run observed no bottleneck at this workload; it does
not identify the first bottleneck at target scale or set a regression budget.

Per-window RSS and reply p95 samples were written to
`target/soak-smoke/movement-60s-samples.csv` for this local run.
